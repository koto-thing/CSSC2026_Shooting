# 東方風弾幕シューティング 実装計画

## 1. 目的

`cssc_game` を、縦スクロール型のオリジナル弾幕シューティングとして完成させる。

- 最新版engineへ更新する
- タイトル、クレジット、メインメニュー、ゲームの4シーンを実装する
- キャラクターとショット種別を別々に選択できるようにする
- 任意数のチャプターで構成できるステージシステムを作る
- 被弾時は死亡したチャプターの開始状態へ戻す
- 約30～40分遊べる5ステージを実装する
- 東方Project系の縦長プレイ領域、弾幕、ボス戦、情報パネルを参考にしつつ、素材と世界観はオリジナルにする

## 2. 確定仕様

### キャラクターとショット

仮キャラクターを3体用意する。

| キャラクター | 移動特性                     | 想定用途         |
| ------------ | ---------------------------- | ---------------- |
| 高速型       | 高速移動、細かな調整は難しい | 道中の素早い移動 |
| 標準型       | 速度と操作性のバランス型     | 初心者向け       |
| 低速型       | 通常速度が低く精密操作向き   | 高密度弾幕の回避 |

ショットはキャラクターとは独立して選択可能にする。

| ショット | 特性                       |
| -------- | -------------------------- |
| 直線     | 正面集中、高い単体火力     |
| 拡散     | 広範囲、道中向き           |
| 追尾     | 敵を自動追尾、火力は控えめ |

選択結果はセッション設定オブジェクトに保存し、ゲームシーン生成時にPlayerへ渡す。

### プレイヤー

- 敵弾または接触判定に一度触れると死亡
- 残機制は採用せず、現在チャプターを再開始する
- 再開始回数に制限は設けない
- 通常移動と低速移動を実装する
- 低速移動中は当たり判定を表示する
- ショットは押し続けて連射できる
- 初期操作案:
  - 移動: 矢印キーまたはWASD
  - ショット: Z
  - 低速移動: Shift
  - ポーズ: Escape

ゲームパッド対応はengineの入力APIで無理なく対応できる場合のみ追加する。

## 3. engine更新

更新元:

`D:\Pandd\cssc_hordesurvival\src\engine`

更新先:

`D:\Pandd\cssc_game\src\engine`

### 更新手順

1. 更新元engine一式を更新先へ同期する
2. 更新元に存在しない旧engineファイルを調査し、参照が残っていないことを確認してから整理する
3. importを新しい公開APIへ移行する
4. `Input` 使用箇所を `InputSystem` に移行する
5. シーンの `Initialize()` を `initialize()` に統一する
6. `MathUtil` / `MathUtils`、Collider、GameObjectなどの変更点へ既存コードを適合させる
7. UIは新engineの `Button`、`Text`、`Image`、`UIElement` などを優先して使用する
8. engineのテストをプロジェクト側のテスト実行環境に含められるか確認する
9. build、起動、シーン切り替え、入力、衝突判定を検証する

engineそのものは原則として更新元を正とし、ゲーム固有の都合による改造は避ける。必要な拡張はゲーム側に置く。

## 4. シーン構成

### 4.1 タイトルシーン

配置:

- 中央上部: ゲームタイトル
- 中央: メインメニューへ進むボタン
- 中央下部: クレジットボタン

動作:

- 「START」でメインメニューシーンへ遷移
- 「CREDITS」でクレジットシーンへ遷移
- 画面全体クリックによる無条件遷移は廃止する
- イベントリスナーは初期化時に一度だけ登録し、終了時に確実に解除する

### 4.2 クレジットシーン

現段階ではプレースホルダーとする。

- 見出し: `CREDITS`
- 本文: `Credits will be added later.`
- 左上: タイトルへ戻るボタン

将来、役割・名前・使用素材・ライセンスを一覧化できる縦方向レイアウトにする。

### 4.3 メインメニューシーン

配置:

- 左上端: タイトルへ戻るボタン
- 中央左: キャラクター選択
- 中央右: ショット選択
- 下部または中央下: 選択内容と操作説明
- 右下端: ゲーム開始ボタン

要件:

- キャラクター3体とショット3種を独立して選択できる
- 現在の選択を枠、色、説明文で明確に示す
- 未選択状態ではゲーム開始を無効化するか、標準型＋直線を初期選択する
- 今回は標準型＋直線を初期選択とする
- ゲーム開始時に選択設定をゲームシーンへ渡す
- リサイズ後も左上・右下のボタンを画面端基準で維持する

### 4.4 ゲームシーン

東方系の画面構成を参考にする。

- 左側または中央: 縦長のプレイ領域（基本比率 3:4）
- 右側: 情報パネル
- プレイ領域外へ敵弾・自機弾・敵・演出が描画されないマスク
- ボス戦中はプレイ領域上部にボスHPと残り時間
- チャプター開始時にステージ名・チャプター名を短時間表示
- 被弾時は死亡演出後、同じチャプターを初期状態から再構築
- 全5ステージ完了後はリザルト表示を経てメインメニューへ戻れる

右側情報パネル:

- `HI SCORE`
- `SCORE`
- `STAGE`
- `CHAPTER`
- `SHOT`
- `GRAZE`
- プレイ時間またはチャプター経過時間
- 操作説明

残機とボムは今回の仕様では使用しない。東方風の見た目を維持しながら、実際に存在しないリソースは表示しない。

## 5. 任意数チャプターシステム

ステージごとのチャプター数を固定しない。データ配列にチャプターを追加・削除するだけで進行が変わる構造にする。

### データ構造案

```js
export const StageDefinition = {
  id: "stage-1",
  name: "Stage 1",
  estimatedSeconds: 360,
  chapters: [
    {
      id: "1-1",
      name: "Opening",
      type: "wave",
      duration: 35,
      events: [],
    },
    {
      id: "1-2",
      name: "Midboss",
      type: "boss",
      boss: {},
    },
  ],
};
```

チャプターの終了条件は複数方式に対応する。

- `duration`: 指定時間経過
- `allEnemiesDefeated`: 登録イベント終了後に敵が全滅
- `bossDefeated`: 対象ボス撃破
- `custom`: 特殊条件用コールバックまたは条件ID

### ChapterControllerの責務

- 現在ステージ・チャプターの管理
- チャプター開始時の状態構築
- 時刻ベースイベントの発火
- 終了条件の判定
- 次チャプター・次ステージへの遷移
- 被弾時の同一チャプター再開始
- 敵、弾、演出、一時タイマーの完全リセット
- スコアなど、再開始時に維持する値と戻す値の管理

### 再開始時の扱い

維持:

- 選択キャラクター
- 選択ショット
- 到達済みステージ・チャプター
- 設定
- 累計プレイ時間

チャプター開始時へ戻す:

- 自機位置
- 自機の一時状態
- 敵とボス
- 自機弾・敵弾
- チャプター内のイベント進行
- チャプター内スコア
- チャプター内グレイズ

スコアはチャプター開始時にスナップショットを保存し、死亡時にその値へ戻す。死亡を繰り返してスコアを稼げないようにする。

## 6. 5ステージ構成

合計目標時間は30～40分。初見時の再挑戦を除き、1ステージ約6～8分を基準とする。

各ステージは6～10チャプター程度を初期案とするが、データ上は任意数にする。

### Stage 1: 星降る庭

目的:

- 基本移動、ショット、低速移動、当たり判定を学ぶ

弾幕:

- 単発狙い弾
- 緩い扇状弾
- 低密度の円形弾

構成例:

1. 導入
2. 左右編隊
3. 狙い弾練習
4. 中ボス
5. 交差編隊
6. 円形弾練習
7. ボス通常
8. ボススペル相当パターン

### Stage 2: 霧の水路

目的:

- 画面全体を見る移動と、弾列の間を抜ける操作

弾幕:

- 波状弾
- 交差弾
- 自機狙い＋固定弾の複合

### Stage 3: 風車の空

目的:

- 回転弾幕と動く安全地帯への対応

弾幕:

- 螺旋
- 回転する放射弾
- 敵の移動と同期する弾列

### Stage 4: 月影の回廊

目的:

- 高密度弾幕と精密な低速移動

弾幕:

- 収束と拡散
- レーザー風予告線＋弾列
- 複数発射源
- 偽の安全地帯を作る時間差弾

### Stage 5: 天頂の祭壇

目的:

- これまでの要素を組み合わせた最終試験

弾幕:

- 狙い弾、固定弾、螺旋、交差弾の複合
- 複数フェーズの中ボス
- 最終ボスの複数通常攻撃と複数スペル相当パターン
- 最終パターンは長めだが、見切れる規則性を持たせる

## 7. 弾幕・敵・ボスの拡張

### 弾幕パターン

既存パターンを整理し、データから組み合わせられるようにする。

- 自機狙い
- n-way扇状
- 全周放射
- 螺旋
- 二重螺旋
- 波状
- リング
- 交差
- 時間差発射
- 加速・減速
- 曲線移動
- 一定時間停止後に再加速
- 予告線付き高速弾

### ボスフェーズ

ボスは複数フェーズを配列で定義する。

```js
phases: [
  { type: "normal", hp: 300, timeout: 30, pattern: "aimedFan" },
  { type: "spell", name: "星符「仮題」", hp: 500, timeout: 45, pattern: "doubleSpiral" },
];
```

- HPを0にするか制限時間終了で次フェーズへ進む
- フェーズ切り替え時に敵弾を消去する
- スペル相当フェーズ名を画面表示する
- タイムアウトは進行停止を避けるために必須とする

## 8. スコアとグレイズ

最低限、次を実装する。

- 敵撃破スコア
- ボスフェーズ撃破スコア
- 敵弾が当たり判定の近くを通過した際のグレイズ
- 同じ敵弾からのグレイズは原則1回
- チャプタークリアボーナス
- ノーミスチャプターボーナス
- ローカルハイスコア

死亡時はチャプター開始時のスコアとグレイズへ戻す。

## 9. 表示・演出

オリジナル素材が揃うまでは、図形、グラデーション、パーティクル、生成した簡易アイコンで統一感を作る。

- 暗い背景と高彩度の敵弾で視認性を確保
- 自機弾と敵弾の色・形を明確に分ける
- 当たり判定は小さく明瞭にする
- 敵弾の中心を明るくし、背景上で埋もれないようにする
- 被弾時は短い停止、爆発、画面フェードを行う
- チャプター再開前にチャプター名を表示する
- ボスフェーズ切り替え時は弾消し演出を入れる
- 過度な画面揺れや背景の明滅は避ける

## 11. 実装順序

### Phase 1: 基盤更新

1. 作業ツリーと既存挙動を確認
2. 最新engineへ同期
3. engine API変更へ既存コードを移行
4. buildと起動を復旧

完了条件:

- `npm run build` 成功
- タイトルシーンが表示される
- コンソールエラーがない

### Phase 2: シーンとメニュー

1. GameSession設定を作成
2. タイトルシーンを更新
3. クレジットシーンを追加
4. メインメニューシーンを追加
5. 全シーンを登録
6. キャラクター・ショット選択を接続

完了条件:

- タイトル→メニュー→ゲームが動作
- タイトル→クレジット→タイトルが動作
- 選択内容がゲームへ渡る
- 画面端ボタンがリサイズ後も正しい

### Phase 3: ゲームプレイ基盤

1. 新入力APIへPlayerを移行
2. 一撃死亡判定を実装
3. 低速移動と当たり判定表示を実装
4. HUDを実装
5. グレイズを実装
6. ポーズを実装

### Phase 4: チャプターシステム

1. ChapterControllerを実装
2. 任意数チャプターデータを読み込む
3. 各終了条件を実装
4. 状態スナップショットを実装
5. 被弾時の完全リセットを実装
6. チャプター間・ステージ間遷移を実装

完了条件:

- チャプター数を変更してもコード変更なしで進行
- 任意チャプターで死亡し、同じチャプター冒頭から同じ敵配置で再開
- 弾・敵・タイマーが前回の状態から残らない

### Phase 5: 5ステージ制作

1. Stage 1を完成し難易度基準を決める
2. Stage 2～4を段階的に追加
3. Stage 5と最終ボスを追加
4. 総プレイ時間を計測
5. 弾速、密度、HP、タイムアウトを調整

### Phase 6: 仕上げと検証

1. 演出と視認性を改善
2. ハイスコア保存
3. リザルトとクリア導線
4. 主要画面サイズで表示確認
5. 長時間プレイでオブジェクト・イベントのリークを確認
6. build成果物を確認

## 12. テスト計画

### 自動テスト候補

- チャプターの順次遷移
- 任意数チャプターの読み込み
- duration / allEnemiesDefeated / bossDefeated終了条件
- 被弾時のチャプター番号維持
- スコアスナップショット復元
- 弾と敵の全消去
- キャラクター・ショット選択の保持
- 同じ敵弾でグレイズが重複しないこと

### ブラウザ確認

- タイトルの2ボタン
- クレジットから戻る
- メニュー左上・右下ボタンの配置
- 3×3の全キャラクター・ショット組み合わせ
- キーボード移動、ショット、低速、ポーズ
- 敵弾への一撃死亡
- 各ステージの複数チャプターで再開位置を確認
- 5ステージ通しプレイ
- 16:9、16:10、4:3、縦長、小さいウィンドウでの表示
- ブラウザのフォーカスを失った際に入力が残らないこと

### 性能基準

- 通常プレイで60 FPSを目標
- 高密度弾幕でも著しい入力遅延を起こさない
- 画面外オブジェクトを確実に回収する
- オブジェクトプールを利用し、弾生成によるGC負荷を抑える
